Flourish & Blotts

Magicstore ❧ Webchat2026 demo builds

Development

dev/

The minified build against the dev backend — the day-to-day demo link.

dev.debug/

Same backend, unminified with verbose SDK logging — for tracing an issue.

Production

prod/

The minified build against the prod backend — the customer-facing artifact.

prod.debug/

Same backend, unminified with verbose SDK logging. Not served from the public host.

The .debug builds are origin-locked exactly like their min siblings — __WEBCHAT2026_FORCED__ follows the vite build mode, not the flavor, so a debug build can log verbosely without opening up which origin it will talk to.

Prod has no live realtime socket (realtime_ws_url is empty in the prod deployment config), so a prod widget runs REST-only and will not stream a reply.
