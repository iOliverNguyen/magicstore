Connectly Webchat

Canvas ❧ Documentation & integration playgrounds

The same site, built twice against two different gateways. Both copies carry the same prose — the documentation is customer-facing and names production URLs on either host — so what a build picks is which backend its live widget and its six integration playgrounds talk to.

Development

dev/

Built against the dev gateway — the copy to open when checking whether a change to the docs site or a playground still works.

Production

prod/

Built against the prod gateway — the mirror of what webchat.connectly.ai/docs/ serves.

There is no .debug flavor and no local build here. The canvas ships two target directories, not six: a debug build makes nothing this site demonstrates more legible, and a local one would build cleanly and then have no backend to reach. Use examples/magicstore for local-backend work.

Prod has no live realtime socket (realtime_ws_url is empty in the prod deployment config), so the widget on the prod build runs REST-only and will not stream a reply.
